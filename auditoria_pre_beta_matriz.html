KAN-23 — Esfuerzo de migración a un dashboard React profesional

Stack actual: cero React/Next.js en el repo. src/dashboard/ es HTML/CSS/JS vanilla servido como estático directo por Express (app.use(express.static(dashboardPath))), sin build step ni bundler.

Tamaño real a portar: index.html (244 líneas) + app.js (1020 líneas: fetch/polling cada 2-10s, modales de auth y rechazo, paginación/orden de matches, theming, sin librería de estado) + style.css (974 líneas, sin framework CSS) + sw.js/manifest.json/ios-onboarding.js (PWA).

A favor: el frontend ya está desacoplado del backend a nivel HTTP — todo es REST/JSON vía fetch() con cookie de sesión. Un dashboard React/Next.js consumiría los mismos endpoints casi sin tocar el backend.

En contra: acoplamiento a nivel de repo/deploy — hoy vive en el mismo proceso Node/Express. Next.js implica decidir despliegue (proxy inverso o build embebido) y tocar src/index.ts + Dockerfile. No hay trabajo React parcial existente: es migración desde cero.

No hay urgencia técnica — el acoplamiento HTTP ya es limpio, así que la migración se puede hacer en cualquier momento sin bloquear el piloto.
